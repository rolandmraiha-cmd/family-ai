## Candidate and measurement boundaries

The candidate uses the same audited llama.cpp b11723 image/release as the QAT
trial, but selects the Q8 model/projector at revision
`3d47a7e680fb9526dcac74335858f0f31acc9c27` of
`ggml-org/gemma-4-31B-it-GGUF`. The model is 32,635,676,896 bytes and projector
809,541,728 bytes. Both pinned files must already be mounted; no paid-startup
download fallback is enabled. The separate modelReferences attachment was
changed with workers stopped and all other GraphQL endpoint fields preserved.

The 48 GB GPU pools, 8192 context, one inference slot, min0/max1, 120s idle
timeout and nine European locations are retained. Q8 uses a 2048-token
microbatch so llama.cpp need not reduce the model's 1120-token vision budget
to the 512-token limit observed in the QAT trial. This must be checked in live
logs, together with memory use and the image result.

RunPod pre-stages the image and model before the first candidate request.
Preparation is recorded separately from request-to-answer time. This is a
comparison of engine, model format and quantization together, rather than
proof that changing just one component produces the difference. A cold process
on cached files is not the same as an uncached host or retained-process resume.

Cold probes reserve USD 0.35 for a 600s provider execution/TTL bound plus 120s
idle at USD 1.75/h. Warm probes use a 60s execution/TTL bound and reserve
USD 0.0875 each, including the full idle allowance. The normal USD 2 daily
admission limit is restored after each probe; monthly USD 20 and historical
usage are retained. No job is silently resubmitted.

## Shutdown, resume and final decision

After the last warm probe finished at 02:38:21 UTC, no further requests were
sent until the worker naturally reached IDLE / zero RUNNING, observed at
02:40:52 UTC. Its configured idle timeout remained 120s; the observed API
transition was later than exactly 120s. No manual recycle was used.

The next bounded request, `q8-cold2`, completed in **6.718s**: provider delay
2.121s and execution 3.982s. Logs retain the same llama.cpp process clock and
cached prompt state, with no second engine-start event. This was a retained
worker/process resume, not a second fresh-process boot. It returned the same
short fi/sv/en response, including the documented Swedish error.

**Decision: retain Q8 on the existing endpoint for its substantial startup
improvement and working integration paths.** This is a bounded operational
acceptance, not comprehensive language, image-detail or browser acceptance.
The known language slips and near-square classification remain documented;
the broader preview PR stays draft. The public model alias, authentication,
GPU pools, min0/max1 and 120s idle are retained. No always-on worker, keepalive
or new paid resource was introduced. Placement includes nine European locations
and is not restricted to Sweden, although both measurements used the same
Swedish A40 host.

The live profile is reproduced offline with:

```powershell
.venv/Scripts/python.exe scripts/build_llamacpp_candidate.py .reference/gemma-q8.json --profile q8
```

This deliberately generates maximum workers **0**. The companion
`.model-cache.json` records the required separate pinned modelReferences
attachment. Applying only the REST/environment body is insufficient. Read back
the attachment while workers are stopped, then restore maximum workers to 1.
The generated entrypoint embeds the reviewed `runpod/llamacpp_worker.py` source;
vLLM-specific environment entries are preserved for rollback but do not control
llama.cpp's arguments. `runpod/gemma-endpoint.json` is the previous FP8 restore
point, rather than a representation of the current live engine.

For rollback, drain active jobs, set maximum workers to 0, restore that complete
FP8 JSON including `MAX_NUM_BATCHED_TOKENS=8192`, and clear container overrides
with `args: ""`. While workers are still stopped, restore modelReferences to
`https://huggingface.co/RedHatAI/gemma-4-31B-it-FP8-dynamic:d4ab4f579dd3516f97d8a6a4c98d0653480bad15`.
Verify image, arguments, full environment and cache attachment before restoring
maximum workers to 1. Do not infer that an environment change restored the cache.
